# 技能中心

管理控制台入口：左侧「业务 Agent 开发」分组 →「技能中心」，hash 路由 `#registry`。

## 功能定位

技能中心是平台侧「原子能力」的唯一注册表，页面副标题为「技能包的开发、CI/CD 流水线、版本管理与分发加载」。它承担四件事：

- 汇总内核内置与业务注册的全部技能，并展示实时验签结论；
- 提供两条注册通道：手动填写元数据注册，或填入 Git 仓库地址由后端 `git clone` 并解析 `skill.yaml` 后注册；
- 展示每次注册所触发的**技能准入流水线**运行记录（Lint / 安全扫描 / 单元测试与冲突检测 / 发布注册），并支持对应用级技能重跑；
- 对应用级技能提供编辑、删除、`skill.yaml` 预览与下载。

技能按 `skill_iri` 前缀划分层级：以 `iri://` 开头判定为**系统级**（内核内置，界面标注「只读」，不可编辑或删除）；其余（如 `skill://app/...`）为**应用级**。

## 页面结构（区块 / Tab / 卡片）

1. **页头**：标题「技能中心 (Skill Registry)」+ 实时状态徽标（Live / 加载中 / 错误），右侧「新建/导入技能」按钮。
2. **统计卡（4 张）**：
   - 已注册技能总数（取列表响应 `count`）；
   - 已验签技能（`signature_status = verified` 计数）；
   - 受信任公钥数（取列表响应 `trusted_key_count`）；
   - 验签异常（`invalid` + `unsigned` + `no_trust_anchor` 之和）。
   后端离线时四张卡统一显示「—」。
3. **筛选栏**：层级 Tab「全部技能 / 系统级 / 应用级」（每个 Tab 尾部带条数角标）+ 搜索框（按技能名称或标签模糊匹配，不区分大小写）。
4. **技能卡片网格**：每张卡展示图标、名称、`分类 · 安全级别`、层级徽标、版本号、签名徽标、描述（两行截断）、标签组（分类 + 安全级别 + 允许角色）。卡片底栏左侧为发布状态，右侧为「详情」以及应用级专属的编辑 / 删除按钮；系统级显示锁形「只读」。
5. **详情弹窗**：包含「查看 skill.yaml」「下载 skill.yaml」按钮、`skill.yaml` 预览代码块、「技能元数据」字段表（IRI / 名称 / 版本 / 分类 / 安全级别 / 允许角色 / 权限 / 描述 / 签名状态 / 输入 Schema / 输出 Schema）、可折叠的「技能准入流水线（真实运行记录）」面板。应用级技能在弹窗底部另有「删除」「编辑」。
6. **新建/导入弹窗**：顶部随输入自动切换三种提示条（手动注册 / Git 导入模式 / 编辑模式），表单含 Git 仓库地址、分支或 Tag、技能目录路径、技能名称、版本号、技能描述、分类、安全级别、技能 IRI、可用角色（RBAC）、权限申请。

:::note
签名徽标共四态：`verified` 已验签、`invalid` 验签失败、`unsigned` 未签名、`no_trust_anchor` 无信任锚。该字段仅在列表接口实时返回，注册响应中不携带。
:::

## 关键操作

1. **按层级与关键字定位技能**：点击 Tab 切换层级，再在搜索框输入名称或标签片段；两个条件为「与」关系。
2. **手动注册技能**：点击「新建/导入技能」→ 保持「Git 仓库地址」为空 → 填写技能名称、技能 IRI（二者必填）、版本号、分类、安全级别 → 至少勾选一个可用角色 → 按需勾选权限申请 → 点击「提交集成」。
3. **从 Git 仓库导入技能**：在「Git 仓库地址」填入 `https://` 或 `git@` 开头的地址（输入框变绿并弹出 Git 导入提示条）→ 填写分支或 Tag、技能目录路径 → 其余字段可留空（留空以仓库内 `skill.yaml` 定义为准）→ 按钮变为「Git 导入」后提交。技能 IRI 留空时自动取仓库名推导为 `skill://app/仓库名`。
4. **查看与下载 `skill.yaml`**：卡片「详情」→「查看 skill.yaml」在弹窗内联展示后端实时生成的清单；「下载 skill.yaml」将同一文本存为 `技能名.skill.yaml`。
5. **查看准入流水线运行记录**：详情弹窗中展开「技能准入流水线」→ 顶部按开始时间选择历史运行（最新在前，通过为绿勾、拦截为红叉）→ 下方显示运行概要（发布状态、来源、触发者、耗时、版本）与各阶段时间线（阶段标题、结论徽标、摘要、耗时、明细行）。
6. **重跑流水线**：仅应用级技能在流水线面板右上出现「重跑流水线」；点击后重新拉取运行记录并自动选中新记录，同时刷新技能列表。
7. **编辑技能**：卡片铅笔图标或详情弹窗「编辑」→ 技能 IRI 置灰不可改（主键）→ 修改名称、版本、描述、分类、安全级别、角色、权限 → 「保存修改」按 IRI 覆盖注册，输入/输出 Schema 与编译模板保持原值。
8. **删除技能**：卡片垃圾桶图标或详情弹窗「删除」→ 浏览器二次确认（提示不可撤销并显示 IRI）→ 成功后刷新列表并关闭弹窗。

## 字段与参数说明

| 字段 | 含义 | 约束或默认值 |
| --- | --- | --- |
| `skill_iri` | 技能唯一标识，注册主键 | 与 Git 仓库地址二选一必填；编辑态只读；`iri://` 前缀视为系统级；缺省由仓库名推导为 `skill://app/仓库名` |
| `name` | 技能名称 | 手动注册与编辑态必填；Git 导入可留空（由 `skill.yaml` 解析），提交时兜底为 `unnamed` |
| `version` | 版本号 | 默认 `1.0.0`；列表展示时自动补 `v` 前缀 |
| `description` | 技能能力与适用场景描述 | 可选 |
| `category` | 分类 | 可选，留空提交为 `application`；卡片上作为「提交者」位展示 |
| `security_level` | 安全级别 | 下拉三选：`normal` 普通（默认）/ `sensitive` 敏感 / `critical` 关键 |
| `allowed_roles` | 可调用该技能的角色（RBAC） | 多选自 `PA`、`DA`、`CA`、`AA`、`USER`；默认 `["DA"]`；不可为空 |
| `skill_types` | 权限申请标签，写入 `skill.yaml` 的 permissions | 由三个复选框映射：外部网络 → `network`（默认勾选）、对象存储 → `oss`、MCP 枢纽 → `mcp` |
| `repo_url` | Git 仓库地址 | 以 `https://`、`http://` 或 `git@` 开头即触发 Git 导入分支 |
| `ref` | 分支或 Tag | 默认 `main` |
| `path` | 仓库内技能目录路径 | 表单默认 `/`；留空提交为 `.` |
| `signature_status` | 实时验签结论 | 只读，取值 `verified` / `invalid` / `unsigned` / `no_trust_anchor` |
| `trusted_key_count` | 受信任公钥数量 | 只读，由列表接口返回 |
| 流水线 `stage` | 准入阶段标识 | 固定四阶段：`lint` 代码静态检查、`security` 安全扫描（签名 + 敏感信息）、`test` 单元测试 & 冲突检测、`publish` 发布注册 (Admission) |
| 流水线 `status` | 单阶段结论 | `passed` 通过 / `warning` 告警 / `failed` 失败 / `skipped` 跳过 |
| `gate_passed` | 门禁是否放行 | 前三阶段无 `failed` 即放行；否则 `publish` 阶段标记为 `skipped` |
| `published` | 是否最终注册发布成功 | 门禁放行且发布成功才为 `true` |
| `source` | 流水线触发来源 | `manual` 手动注册 / `git` Git 导入 / `rerun` 手动重跑 |

## 依赖接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/skills` | 拉取技能列表、总数与受信任公钥数（页面每 30 秒轮询） |
| POST | `/api/v1/skills` | 手动注册技能；编辑态按 `skill_iri` 覆盖已注册技能 |
| DELETE | `/api/v1/skills?iri=...` | 删除应用级技能（系统级由后端拒绝） |
| GET | `/api/v1/skills/manifest?iri=...` | 获取后端实时生成的 `skill.yaml` 文本，供预览与下载 |
| POST | `/api/v1/skills/import-git` | 从 Git 仓库克隆并解析 `skill.yaml` 后注册 |
| GET | `/api/v1/skills/pipeline-runs` | 查询准入流水线运行记录，支持 `iri` 过滤与 `limit` 限量（页面取最近 20 条） |
| POST | `/api/v1/skills/pipeline-rerun` | 对已注册的应用级技能重跑准入流水线 |

写操作（注册、删除、Git 导入、重跑）由控制台附带管理身份头，以 DA 角色通过后端角色校验。

## 排查与注意事项

- **列表为空且提示「后端未连接」**：说明列表接口调用失败，统计卡显示「—」。先确认后端服务与控制台的接口基址配置一致。
- **提交报「请填写技能名称」/「请填写 Git 仓库地址或技能 IRI」/「请至少选择一个可用角色」**：均为前端校验，按提示补齐后重试。
- **Git 导入失败**：后端需具备访问该仓库的网络与凭据条件，且目标路径下存在可解析的 `skill.yaml`；仓库地址为空或非法时后端返回 400。
- **删除系统级技能被拒**：`iri://` 前缀技能为内核内置，前端不提供删除入口，直接调用接口会被后端以 403 拒绝。
- **流水线面板提示「暂无运行记录」**：该技能尚未产生运行记录，可重新注册或点击「重跑流水线」生成。
- **验签异常计数偏高**：`unsigned` 表示技能未携带签名，`no_trust_anchor` 表示缺少可用信任锚，`invalid` 表示签名与内容不匹配。前两者通常是签名与信任锚未配置，后者需重新签名后再注册。
- **门禁通过但未发布**：运行概要会显示「门禁通过但未发布」，表示前三阶段无失败但 `publish` 阶段未成功，需查看该阶段明细行定位原因。
- **编辑不会改动 Schema 与模板**：编辑仅覆盖元数据字段，输入/输出 Schema 与编译模板沿用原注册值；若需变更，请通过重新注册或 Git 导入提供完整定义。
- **重跑按钮不出现**：系统级技能不允许重跑，面板不渲染该按钮。

:::tip
批量交付「新能源车维修智能体」的能力包时，建议统一走 Git 导入：仓库内维护 `skill.yaml` 作为唯一事实来源，控制台表单只在需要临时覆盖分类或角色时填写，避免元数据在两处漂移。
:::
