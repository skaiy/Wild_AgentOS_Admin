# 批处理运维

页面入口：左侧导航「调试监控与运维 → 批处理运维」，深链 hash 为 `#batch`。

## 功能定位

「批处理运维台 (Batch Agents)」是平台运维态页面，用于管理**滑动窗口式事件处理智能体**。这类智能体不由用户对话触发，而是持续消费流入的事件，攒够一个窗口后触发一次抽取，把结果沉淀为实体与关系。

本页提供三类能力：

1. **看状态**——批处理系统整体是否运行，每个批处理 Agent 处于何种状态；
2. **看窗口与指标**——当前窗口条目数、累计抽取次数、实体/关系产出、成功与失败计数；
3. **做启停**——对单个批处理 Agent 执行启动或停止。

批处理 Agent 的**存在与否由后端配置文件（`config.yaml`）声明**，管理台不提供新增/删除入口；本页只负责运行期的启停与观测。

:::warning
启停操作需要 DA 角色权限，且会实时改变生产数据流。停止某个批处理 Agent 后，其窗口内尚未触发抽取的事件将不再被处理，请在业务低峰期操作。
:::

## 页面结构（区块/Tab/卡片，与代码一致）

**页头**

- 标题「批处理运维台 (Batch Agents)」，副标题「平台运维态 · 滑动窗口事件处理，按 name + business_domain 组织」。
- 系统状态徽标：绿色「系统 运行中」或灰色「系统 未运行」，对应接口返回的 `running` 字段。
- 右侧「刷新」按钮，手动重新拉取全量数据（加载中图标旋转）。

**错误条**

任何列表或启停请求失败时，页头下方出现红底错误提示，展示后端返回的错误信息原文。

**空态卡片**

无任何批处理 Agent 时显示：「暂无批处理 Agent（config.yaml 中未配置或未启用）」；加载中显示「加载中…」。

**Agent 卡片**（两列栅格，每个批处理 Agent 一张）

卡片自上而下分三段：

1. **标识段**：Agent 名称 + 状态标签；下方一行为描述（缺省 `—`）；再下一行为标签组——业务域、模型（配置了才显示）、「已禁用」红标（`enabled` 为 false 时显示）。
2. **指标段**（2×2 四格）：
   - 窗口条目（`window.entry_count`）
   - 累计抽取（`metrics.total_extractions`）
   - 实体 / 关系（`total_entities_found / total_relations_found`）
   - 成功 / 失败（`success_count / failure_count`）
3. **操作段**：绿色「启动」按钮与深灰「停止」按钮；操作进行中显示「处理中…」。

**状态标签配色与含义**

| 状态 | 配色 | 含义 |
| :-- | :-- | :-- |
| `Registered` | 蓝 | 已注册但未启动 |
| `Running` | 绿 | 正在消费事件 |
| `Paused` | 琥珀 | 已暂停 |
| `Stopped` | 灰 | 已停止 |
| `Error` | 红 | 异常，标签显示为 `Error: 具体信息` |

**按钮禁用规则**（与代码一致）

- 状态为 `Running` 时「启动」按钮禁用；
- 状态为 `Stopped` 时「停止」按钮禁用；
- 该 Agent 正在处理启停请求时两个按钮同时禁用。

## 关键操作（编号步骤）

1. 进入「批处理运维」，先看页头徽标确认「系统 运行中」。若显示「系统 未运行」，则所有单体启停都不会生效，需先在后端启用批处理系统。
2. 浏览卡片列表，按状态标签分类：`Error` 优先处理，`Registered`/`Stopped` 确认是否为预期停用。
3. 启动某个批处理 Agent：点击卡片内绿色「启动」→ 按钮进入禁用态并显示「处理中…」→ 请求成功后页面自动重新拉取全量数据，状态标签应变为 `Running`。
4. 停止某个批处理 Agent：点击深灰「停止」，流程同上，状态应变为 `Stopped`。
5. 启停后核对指标：「窗口条目」在启动后应逐步增长，「累计抽取」在窗口触发后递增。
6. 若指标长时间不动，点击右上角「刷新」确认不是页面数据陈旧——本页**不做自动轮询**，所有更新依赖手动刷新或启停后的自动重载。
7. 出现红色错误条时，读取其中的后端原文信息定位原因（常见为权限不足或批处理系统未启用），处理后再重试。

## 指标与字段说明

| 指标或字段 | 含义 | 判读建议 |
| :-- | :-- | :-- |
| 系统状态 `running` | 批处理系统整体是否在运行 | 为 false 时单体启停无意义，须先启用批处理系统 |
| 名称 `name` | 批处理 Agent 唯一名称 | 启停接口以此名称定位，须与配置文件中的声明一致 |
| 状态 `status` | 运行状态枚举 | `Error` 需立即处理；长期 `Registered` 说明从未被启动 |
| 描述 `config.description` | 配置中的说明文本 | 缺省显示 `—`，不影响运行 |
| 业务域 `config.business_domain` | 该 Agent 所属业务域 | 与名称共同构成「按 name + business_domain 组织」的定位维度 |
| 模型 `config.model` | 该 Agent 抽取使用的模型 | 未配置时回退到网关默认模型（见「运行时内核」页配置区块） |
| 启用标记 `config.enabled` | 配置层是否启用 | 为 false 时卡片显示「已禁用」红标；此时即使手动启动也应视为临时行为，长期生效需改配置 |
| 窗口条目 `window.entry_count` | 当前滑动窗口内累积的条目数 | 一直为 0 说明没有事件流入；只增不触发说明未达触发阈值 |
| 累计抽取 `metrics.total_extractions` | 累计触发抽取的次数 | 与窗口触发次数对应；长期为 0 而窗口条目很多，需检查触发条件 |
| 实体 / 关系 `total_entities_found` / `total_relations_found` | 累计抽出的实体数与关系数 | 抽取次数增长而实体关系为 0，说明抽取提示词或模型输出解析有问题 |
| 成功 / 失败 `success_count` / `failure_count` | 抽取成功与失败累计次数 | 失败占比升高优先看模型可用性与超时配置 |
| 累计 Token `total_tokens_consumed` | 该 Agent 累计消耗的 Token | 用于成本核算（接口返回，卡片当前未直接展示） |
| 最近结果 `last_outcomes` | 最近若干次抽取的成功布尔序列 | 用于判断失败是偶发抖动还是持续故障（接口返回，卡片当前未直接展示） |
| 窗口时间边界 `window.oldest` / `window.newest` | 窗口内最早与最新条目时间 | 两者跨度过大说明事件流入稀疏（接口返回，卡片当前未直接展示） |
| 窗口摘要标记 `window.has_summary` | 窗口是否已生成摘要 | 结合 `last_trigger` 判断上一轮触发是否完成 |
| 上次触发 `window.last_trigger` | 上一次窗口触发时间 | 距今过久且窗口条目在增，说明触发链路异常 |

## 依赖接口

| 方法 | 路径 | 用途 |
| :-- | :-- | :-- |
| GET | `/api/v1/batch/agents` | 列出所有批处理 Agent 及其状态、窗口、指标、配置摘要，并返回系统整体 `running` |
| POST | `/api/v1/batch/agents/{name}/control` | 启停指定批处理 Agent，请求体 `action` 取值 `start` 或 `stop`；需 DA 角色 |

启停请求成功后，页面会立即重新调用列表接口，因此卡片状态与指标为操作后的最新值。

## 排查与注意事项

- **「暂无批处理 Agent」**：绝大多数情况是后端配置中未声明批处理 Agent 或全部未启用，而非接口故障。确认配置后重启后端再刷新本页。
- **提示「批处理系统未启用」/「批处理系统未初始化」**：后端未装载批处理管理器，启停接口会返回 503。此时页头徽标通常显示「系统 未运行」，需在部署侧启用批处理能力。
- **启停返回权限错误**：控制接口要求 DA 角色，管理台请求会自动附带管理身份头。若仍失败，需核对后端的鉴权模式与角色配置。
- **`action` 仅支持 `start` 与 `stop`**：后端对其他取值直接返回 400，页面按钮已限制为这两种操作，请勿绕过页面手工构造其他动作。
- **页面无自动刷新**：本页不做定时轮询。观察窗口增长时需周期性点击「刷新」，否则容易误判为「指标不动」。
- **状态显示 `Error: ...`**：括号后的文本是后端返回的原始错误，通常指向模型调用失败或配置缺项。修复后先「停止」再「启动」，以确保内部状态重置。
- **停止不等于清空**：停止只是不再消费新事件，累计指标与已沉淀的实体关系不会回滚。指标为累计值，不要期待重启后归零。
- **启停会影响下游知识沉淀**：批处理产出会写入图谱与共享黑板，长时间停止会造成知识断档，恢复后需评估是否需要补跑历史事件。
