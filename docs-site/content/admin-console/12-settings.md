# 系统设置与模型注册中心

页面入口：左侧导航栏底部固定按钮「系统设置」，深链 hash 为 `#settings`。页面副标题为「模型注册中心（网关路由 / 向量 / 多模态）、IAM 集成与安全策略」。

## 功能定位

「系统设置」是平台的**运行期配置面板**，把所有需要人工调参的后端配置集中到一处，并且**免重启即时生效**：

1. **模型注册中心**——统一管理外部 API 接入点（Provider）与其下的型号（Resource），覆盖文本、多模态、向量、语音、实时五类模态；同时管理未命中注册表时的兜底网关与生效向量服务。
2. **平台策略**——IAM 令牌与二次验证策略、AI 安全与合规阈值、数据保留期与备份策略。
3. **对外 API 治理**——调用方（Client）、密钥签发与撤销、限流配额与调用审计。

页面上的所有写操作最终都落在同一个后端入口 `PUT /api/v1/config`（API 密钥治理除外，它有独立的资源接口）。后端先把补丁持久化到工程内的 `data/config_override.json`（该文件的优先级高于 `config.yaml`，进程重启时被配置加载器读取），再对运行时对象做热更新，因此**保存即生效，且重启后不丢**。

页面顶部会出现一条保存结果提示：绿色为成功（文案形如「XX 已保存并持久化」），红色为失败并附后端返回的错误原因。当后端未连接时，各分区的「保存」按钮处于禁用态。

## 页面结构

页面为左右两栏：左侧是设置项二级导航，右侧是对应分区内容。二级导航共 5 项，默认停留在「模型注册中心」。

| 二级导航 | 内容概要 | 写入方式 |
| --- | --- | --- |
| 模型注册中心 | Provider 列表、型号列表（按模态分子 Tab）、高级 Embedding 配置、路由/默认（兜底网关） | `PUT /api/v1/config` 的 `models` / `embedding` / `gateway` 段 |
| IAM 身份与访问 | 令牌有效期、高危操作二次验证；右侧为只读 RBAC 角色清单 | `PUT /api/v1/config` 的 `admin_policies.iam` |
| 安全与合规策略 | 提示注入防护、幻觉阈值、工具调用上限、个人信息脱敏 | `PUT /api/v1/config` 的 `admin_policies.security` |
| 数据存储与备份 | 任务/会话/审计三类数据的在线保留期；右侧为只读备份策略说明 | `PUT /api/v1/config` 的 `admin_policies.storage` |
| API 密钥管理 | 调用方、密钥、限流配额、调用审计 | 独立的调用方与密钥接口 |

### 模型注册中心

分区标题右侧有实时徽标与两个动作：「从后端刷新」（仅后端在线时出现，丢弃本地未保存编辑并重新拉取快照）、「保存并生效」。分区自上而下由四块组成：

**1）Providers（外部 API 接入点）**

每个 Provider 一张卡片，字段包含显示名、启用开关、`base_url`、`api_key`、`kind`、`timeout_seconds`，并带「拉取型号」与删除按钮。密钥输入框为密码框；若后端快照标记该 Provider 已配置密钥，占位文案显示「（已配置，留空则不修改）」。

**2）型号（按模态分子 Tab）**

子 Tab 依次为：文本、多模态(VL)、向量、语音、实时，标签后带该模态下的型号数量。右上角「新增 X 型号」会按当前子 Tab 预置模态（例如在「多模态(VL)」下新增会预置 `chat` 与 `vision`）。列表按当前子 Tab 过滤：语音 Tab 同时匹配 `audio_asr` 与 `audio_tts`。

每张型号卡片包含显示名、所属 Provider 下拉、真实型号名 `model`、模态多选、启用/工具/推理三个能力开关，以及「连通性测试」「删除」按钮；向量型号额外要求填写 `dimension`，非向量型号则可选填 `context_window`。

**3）向量 Tab 的生效向量信息条与高级配置**

切到「向量」子 Tab 时，顶部显示当前生效向量：若来自注册表桥接，展示型号名与生效维度；否则提示「非注册表桥接」并显示当前 provider 与维度。未生效的向量型号卡片上会出现「设为生效向量」按钮；已生效的卡片显示绿色「生效中」标记。

Tab 底部为可折叠的「高级：原始 Embedding 配置（ollama / 内置降级）」，用于私有化、离线或不走注册表桥接的场景：可选 `ollama`（本地/私有）、`oneapi`（OpenAI 兼容网关）、`fallback`（内置确定性向量）三种 provider，并分别填写 `base_url` / `model` / `dimension`（`oneapi` 另有密钥字段，留空不修改）。

**4）路由 / 默认（兜底网关）**

当请求的模型名未命中上方注册表型号时，网关回退到这里配置的默认端点与默认模型。字段为网关 Base URL、API Key（已配置时留空即保留原值）、默认模型、超时(秒)、最大重试，动作按钮为「推送网关」。下方表格只读展示 `model_mapping`（「请求模型名 → 实际路由到」），未配置额外映射时提示所有请求走默认模型。

### 其余四个分区

- **IAM 身份与访问**：左列为「认证与 Token 策略」（Access Token 有效期、Refresh Token 有效期、高危操作二次验证），右列为只读的「细粒度 RBAC 角色」清单（平台管理员、技能开发者、业务操作员、数据分析师、只读访客）。
- **安全与合规策略**：上半部为「AI 特有安全防护」（提示注入防护、幻觉控制阈值、过度代理防护），下半部为「数据安全与隐私保护」（个人信息自动脱敏；「强制 TLS 1.3 传输加密」为固定开启的只读项）。
- **数据存储与备份**：左列为在线保留期（任务执行记录、会话上下文、审计日志），右列为只读的自动备份策略说明（关系库每日全量加每小时增量并加密异地存储；向量库每日快照；图数据库每日全量导出并保留最近 7 个版本）。
- **API 密钥管理**：顶部「新建调用方」，中部按调用方分组展示授权范围、限流配额、实时用量与名下密钥表格，底部为「调用审计（最近 100 条）」及调用方过滤下拉。

## 关键操作（编号步骤）

**接入一个新的模型服务商并挂载型号**

1. 进入 `#settings`，停留在「模型注册中心」，确认标题右侧徽标为「实时」。
2. 点「新增 Provider」，填写显示名与 `base_url`，粘贴密钥，按需调整 `timeout_seconds`，保持「启用」勾选。
3. 点该 Provider 卡片上的「拉取型号」。系统调用其 `/v1/models` 拉取可用型号，并自动过滤掉该 Provider 下已添加的型号。
4. 在弹出的选择器中勾选需要的型号；每行的模态由型号名关键词自动预判，若判断有误可直接在下拉中改正，然后点「添加所选」。
5. 点右上角「保存并生效」。保存成功后提示「已保存并热更新（免重启即时生效）」，且密钥输入框被清空（后端不回显明文）。
6. 对关键型号点「连通性测试」，确认返回绿色结果（HTTP 状态与延迟毫秒数）。

**将某个向量型号设为生效向量**

1. 切到型号区的「向量」子 Tab，确认目标向量型号已填写正确的 `dimension`（缺失时点击按钮会直接提示补填维度）。
2. 建议先对该型号做一次「连通性测试」：向量模态的测试结果会额外返回探测到的实际维度，可与填写值核对。
3. 点「设为生效向量」。系统会先保存注册表（确保 Provider 密钥已持久化），再执行激活，随后刷新快照。
4. 等待提示成功后，观察信息条中的「当前生效向量」是否已变为该型号及其维度。
5. 到「知识中心」确认各向量知识库的索引重建任务已完成后，再执行线上检索类业务。

**调整平台策略**

1. 切到「IAM 身份与访问」/「安全与合规策略」/「数据存储与备份」任一分区。
2. 修改表单项（下拉、数字框、开关）。
3. 点该分区右上角「保存配置」，等待页面顶部出现绿色成功提示。三个分区共用同一份策略对象，任一分区保存都会提交完整策略。

**开通一个对外调用方并签发密钥**

1. 切到「API 密钥管理」，点「新建调用方」。
2. 填写名称（必填）与描述，在「授权可调用的 Agent（scope）」中勾选允许调用的智能体，设置 `rpm`、最大并发、日配额、月配额（填 0 表示不限）后点「创建」。
3. 在调用方卡片上点「签发密钥」，填写密钥名称（留空则命名为「默认密钥」）后点「签发」。
4. 在弹出的「密钥已生成」窗口中点「复制」并立即妥善保存——**明文仅此一次显示，关闭后无法再次查看**。
5. 后续可对调用方执行「停用/启用」、对单把密钥执行「撤销」，或删除整个调用方（需二次确认，其名下所有密钥一并失效）。
6. 在「调用审计」中按调用方过滤，核对端点、返回状态与耗时。

## 字段与参数说明

**Provider（外部 API 接入点）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 字符串 | 新增时前端自动生成（形如 `prov-xxxxxxxx`），型号通过它关联 Provider，请勿随意改动 |
| `name` | 字符串 | 显示名，仅用于界面与下拉选择 |
| `base_url` | 字符串 | OpenAI 兼容服务根地址。**写不写结尾的 `/v1` 都可以**：后端会去掉结尾斜杠并剥离结尾的 `/v1`，各调用点再统一拼接 `/v1/...`，从而避免出现 `/v1/v1/...` 导致的 404 |
| `api_key` | 字符串 | 仅在提交时上行。**留空表示沿用原值**；快照中只回显「是否已配置」的布尔标志，绝不回显明文 |
| `kind` | 枚举 | 当前仅支持 `openai_compatible` |
| `enabled` | 布尔 | 关闭后该 Provider 及其型号不会被灌入网关 |
| `timeout_seconds` | 整数 | 默认 60。连通性测试与拉取型号会把它钳制在 3–60 秒区间内使用 |

**型号（Model Resource）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 字符串 | 新增时自动生成（形如 `res-xxxxxxxx`），智能体的能力槽挂载与向量激活都按它定位 |
| `name` | 字符串 | 显示名；从「拉取型号」添加时默认取型号原名 |
| `provider_id` | 字符串 | 所属 Provider 的 `id`，为空则无法测试与路由 |
| `model` | 字符串 | **真实型号名**，即最终发给服务商请求体里的 `model` 字段 |
| `modalities` | 字符串数组 | 可选值：`chat`、`vision`、`embedding`、`audio_asr`、`audio_tts`、`realtime`；勾选/取消 `vision` 会同步 `supports_vision` |
| `enabled` | 布尔 | 关闭后不会进入网关的「型号 → Provider」映射 |
| `dimension` | 整数 | **向量型号必填**。作为生效向量时决定向量库维度；未填写无法激活 |
| `context_window` | 整数 | 非向量型号可选，仅作登记用途 |
| `supports_tools` / `supports_reasoning` | 布尔 | 能力标记，供智能体挂载与调度参考 |

**拉取型号时的模态预判规则**（型号列表接口不返回模态，故按名称关键词猜测，结果允许人工修改）

| 名称中包含 | 预判模态 |
| --- | --- |
| `embed`、`bge`、`gte`、`m3e`、`text-embedding` | `embedding` |
| `realtime` | `realtime` |
| `tts`、`speech`、`voice` | `audio_tts` |
| `asr`、`whisper`、`audio` | `audio_asr` |
| `-vl`、`vl-`、`vision`、`multimodal`、`omni`、`image` | `vision`（添加时自动带上 `chat`） |
| 其他 | `chat` |

**连通性测试的探测方式**

| 模态 | 探测请求 | 结果字段 |
| --- | --- | --- |
| `chat` 及其他 | `POST {base}/v1/chat/completions`，最小消息体、`max_tokens: 1` | `ok`、`http_status`、`latency_ms` |
| `vision` | 同上，附带一张 32×32 的最小测试图片（部分 VL 型号要求图片每边大于 28 像素） | 同上 |
| `embedding` | `POST {base}/v1/embeddings`，输入一个极短字符串 | 额外返回 `dimension`（实际返回向量长度） |

测试结果中**不包含任何密钥**，网络失败时只回传网络层原因（`http_status` 为 0）。

**兜底网关（路由 / 默认）**

| 字段 | 说明 |
| --- | --- |
| `base_url` | 未命中注册表型号时使用的默认端点 |
| `api_key` | 留空表示保留后端原值；已配置时字段旁显示「已配置（留空不改）」 |
| `default_model` | 未命中 `model_mapping` 时实际使用的模型 |
| `timeout_seconds` / `max_retries` | 网关请求超时与最大重试次数 |
| `model_mapping` | 只读展示的「请求模型名 → 实际部署模型」映射 |

**平台策略字段**

| 分区 | 字段 | 可选值 / 范围 |
| --- | --- | --- |
| IAM | `access_token_hours` | 1 / 2 / 4 / 12 小时 |
| IAM | `refresh_token_days` | 1 / 3 / 7 / 30 天 |
| IAM | `mfa_for_sensitive_actions` | 开 / 关（删除、发布等高危操作强制二次验证） |
| 安全 | `prompt_injection_protection` | 开 / 关 |
| 安全 | `hallucination_threshold` | 0–1，步长 0.01；一致性评分低于该值触发拦截或转人工复核 |
| 安全 | `max_tool_calls` | 1–100 次/任务 |
| 安全 | `pii_redaction` | 开 / 关（推理前替换姓名、手机号、证件号等敏感信息） |
| 存储 | `task_retention_days` | 30 / 90 / 180 天 |
| 存储 | `session_retention_hours` | 24 / 72 / 168 小时（过期直接删除，不归档） |
| 存储 | `audit_retention_days` | 180 / 365 / 1095 天 |

**调用方与密钥字段**

| 字段 | 说明 |
| --- | --- |
| `name` / `description` | 调用方名称（必填）与用途描述 |
| `granted_agent_ids` | 授权可调用的智能体范围；仅「已发布」的智能体才能被外部实际调用 |
| `rate_limit.rpm` / `rate_limit.concurrency` | 每分钟请求数与最大并发，0 表示不限 |
| `quota.daily` / `quota.monthly` | 日配额与月配额，0 表示不限 |
| `usage.*` | 实时用量快照：本分钟请求数、当前并发、今日已用、本月已用 |
| `key_prefix` | 密钥前缀，列表中以「前缀 + 掩码」形式展示；明文不入库、不回显 |
| `status` | 调用方为启用/停用；密钥为正常/已撤销 |

## 配置保存语义

理解下面四条语义，可以避免绝大多数「保存后没生效」或「密钥被清空」的误判：

1. **先落盘再热更**。`PUT /api/v1/config` 首先把补丁合并写入 `data/config_override.json`；写盘失败会直接返回错误且不做运行时变更。该文件优先级高于 `config.yaml`，因此重启后配置依然保持。
2. **`models` 段是整体替换**。`providers` 与 `resources` 采用集合语义：提交的数组就是最终状态，本地删掉的条目保存后即被移除。相对地，`gateway`、`embedding`、`admin_policies` 走深合并，只覆盖提交到的字段。
3. **密钥留空表示沿用原值**。前端会把未填写密钥的 Provider 剔除该字段；后端在落盘时按 Provider 的 `id` 回填此前持久化的旧密钥，网关密钥与向量网关密钥同理。空字符串同样不会被写入，从而不会覆盖既有密钥。
4. **热更新范围**。提交 `models` 会把「启用的 Provider 端点」与「型号 → Provider 映射」重新灌入网关（未命中的模型自动回退兜底网关）；提交 `embedding` 会重建向量服务、原子换入新维度向量库，并在后台按原文台账重建所有向量知识库索引，响应中的 `embedding_reloaded` 与 `reindex_queued` 即为该动作的结果。

:::warning
「连通性测试」与「设为生效向量」读取的是**已持久化**的注册表，因此这两个动作都会先自动保存当前本地编辑态。若不希望提交当前草稿，请先点「从后端刷新」放弃本地修改。
:::

## 排查与注意事项

- **变更前先备份**。调整注册表、向量或网关前，建议备份工程内的 `data/config_override.json`；该文件即整份运行期覆盖配置，回滚时替换后重启即可。向量热切换时旧向量库目录会被整体改名为带时间戳的 `.bak-` 备份目录，便于回滚与比对。
- **测试提示「provider 未找到」**：多为 `provider_id` 未选择或该 Provider 尚未保存。检查型号卡片的 Provider 下拉，再点「保存并生效」后重试。
- **测试返回 404**：优先检查 `base_url`。虽然结尾的 `/v1` 会被自动剥离，但把网关控制台地址、带额外前缀的路径填成 `base_url` 仍会导致路径拼接后不存在。
- **测试返回 401 / 403**：密钥未配置、已过期或无该型号权限。重新填写密钥并保存（留空不会覆盖旧值，需明确填入新值）。
- **激活向量报「provider 未配置 api_key」**：作为 OpenAI 兼容向量服务生效要求 Provider 同时具备 `base_url` 与密钥，请补齐后先保存再激活。
- **切换生效向量后检索结果异常**：旧向量由旧模型产生，语义空间不可混用，必须等待索引重建完成。维度变化时结构本身也不兼容。重建为后台任务，向量库较多或文档量大时请预留时间，并尽量安排在业务低峰执行。
- **删除生效中的向量型号**：会弹出二次确认，确认后系统一次性提交「移除该型号」与「回退到本地内置向量」，同样触发索引重建。请勿在业务高峰执行。
- **保存按钮为灰色不可点**：后端未连接（徽标非「实时」）。此时所有写操作被禁用，先排查后端服务与网络连通性。
- **密钥管理相关接口需要管理身份头**：调用方与审计接口带管理端身份标识发送，若返回权限错误，请确认当前登录账号具备管理角色。
- **签发的密钥明文只显示一次**：未及时保存只能撤销后重新签发；请勿把明文记录在工单、聊天记录等非受控位置。
- **只读项不可修改**：RBAC 角色清单、备份策略说明、`model_mapping` 表格与「强制 TLS 1.3」开关均为展示项，需要变更请通过后端配置与部署流程处理。
