# MCP 枢纽

管理控制台入口：左侧「业务 Agent 开发」分组 →「MCP枢纽」，hash 路由 `#mcp`。

## 功能定位

页面标题为「MCP Hub (多模态能力枢纽)」，副标题「连接外部工具与数据源的标准接口，统一限流与熔断管理」。它是平台对接外部工具与数据源的登记入口，职责有三：

- 登记外部 MCP 服务：名称、协议、描述、Endpoint URL；
- 汇总注册表规模与健康分布（已注册 / 在线 / 异常告警）；
- 以列表形式呈现每个服务的协议、描述、端点与状态，供智能体侧引用与运维侧巡检。

页面自身是**注册与查看**视图：它不提供编辑、删除、连通性探测或限流阈值配置的操作入口；健康状态取自后端返回的 `status` 字段，页面只负责按取值着色。

## 页面结构（区块 / 卡片）

1. **页头**：标题「MCP Hub (多模态能力枢纽)」+ 副标题 + 实时状态徽标（该徽标绑定后端健康检查，而非 MCP 列表本身），右侧「注册新 MCP」按钮。
2. **统计卡（3 张）**：
   - 已注册 MCP 服务：取列表响应的 `count`，单位「个」；
   - 在线服务数：`status` 为 `healthy` 或 `online` 的条数；
   - 异常/警告服务：`status` 不为 `healthy` 且不为 `online` 的条数。
3. **「已注册 MCP 服务」列表卡**：
   - 卡头左侧为服务器图标、标题与总数角标；右侧为状态图例：绿点「正常」、琥珀点「警告」、红点「离线」。
   - 列表每行左侧按协议区分图标（`http` 为数据库图标，其余为服务器图标），随后是服务名称、协议圆角标签、描述（存在时显示）、等宽字体的 Endpoint 地址；右侧是状态圆点与 `status` 原始文本。
   - 空态两种文案：后端可达但无数据显示「暂无注册的 MCP 服务，点击右上角「注册新 MCP」添加」；后端不可达显示「后端离线，无法加载 MCP 服务列表」。
4. **「注册新 MCP 服务」弹窗**：
   - 第一行左右两列：「MCP 名称 *」文本框、「协议」下拉（`SSE` / `stdio` / `HTTP`）；
   - 「服务描述」多行文本域；
   - 「Endpoint URL *」等宽输入框；
   - 琥珀色提示条：「注册后服务器将添加到实时注册表（运行期内存，重启后清空）。」；
   - 失败时在提示条下方追加红色错误条；
   - 底部「取消」「注册服务」，名称或端点为空时「注册服务」保持禁用。

:::note
状态圆点的着色规则为：`healthy` / `online` 绿色，`warning` / `degraded` 琥珀色，其余取值（含新注册后的默认值）红色。圆点旁始终显示后端返回的原始状态文本，便于核对。
:::

## 关键操作

1. **查看注册表概况**：进入页面即自动加载，列表每 30 秒轮询刷新一次；先看三张统计卡判断规模与异常数量，再到列表定位具体服务。
2. **注册新 MCP 服务**：
   - 点击右上「注册新 MCP」打开弹窗；
   - 在「MCP 名称」填写可辨识的服务名；
   - 在「协议」下拉中选择传输方式，默认 `SSE`；
   - 「服务描述」简述该服务提供的能力（可留空）；
   - 在「Endpoint URL」填写完整可访问地址；
   - 点击「注册服务」，按钮进入「注册中…」状态；成功后弹窗关闭、名称/端点/描述输入清空，列表自动刷新。
3. **按协议识别服务类型**：列表行首图标与协议标签一并展示，`http` 类服务与流式/进程类服务可直接肉眼区分。
4. **排查异常服务**：「异常/警告服务」计数大于 0 时，在列表中查找非绿点行，读取其右侧原始 `status` 文本与 Endpoint，再到外部服务侧核实。
5. **取消注册操作**：点击弹窗右上关闭图标、底部「取消」或点击遮罩层均可关闭弹窗；已输入内容在下次打开时仍会保留（仅注册成功才清空）。

## 字段与参数说明

| 字段 | 含义 | 约束或默认值 |
| --- | --- | --- |
| `name` | MCP 服务名称 | 必填，去除首尾空格后不能为空，否则「注册服务」按钮禁用 |
| `endpoint` | MCP 服务端点地址 | 必填，去除首尾空格后不能为空；填写外部服务可访问的完整 URL |
| `description` | 服务能力描述 | 可选，留空时后端存为空字符串，列表不渲染描述行 |
| `protocol` | 传输协议 | 下拉三选：`sse`（页面默认）/ `stdio` / `http`；请求未携带该字段时后端回落为 `sse` |
| `id` | 服务唯一标识 | 由后端生成的 UUID，注册成功时返回 |
| `status` | 服务健康状态 | 只读；新注册记录后端写入 `active`；页面仅对 `healthy` / `online` 判定为在线，`warning` / `degraded` 判定为警告 |
| `count` | 已注册服务总数 | 只读，来自列表接口 |
| 注册响应 `status` | 注册结果标识 | 只读，成功返回 `registered`，HTTP 状态码 201 |

## 依赖接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/mcp/servers` | 拉取已注册 MCP 服务列表与总数（页面每 30 秒轮询） |
| POST | `/api/v1/mcp/servers` | 注册新的 MCP 服务（提交 name / endpoint / description / protocol） |
| GET | `/health` | 页头实时状态徽标所依赖的后端健康检查（每 10 秒轮询） |

## 排查与注意事项

- **页头徽标显示在线但列表为空**：页头徽标绑定的是后端健康检查，与 MCP 列表接口相互独立。若列表提示「后端离线，无法加载 MCP 服务列表」，说明列表接口单独失败，需查看后端该路由的日志。
- **「注册服务」按钮点不动**：名称或 Endpoint URL 为空（或仅含空格）时按钮为禁用态，补齐两项必填即可。
- **注册失败弹出红色错误条**：错误条优先展示后端返回的错误信息，无法解析时回落为「注册失败，请检查端点地址或后端日志」。常见原因是端点格式非法或后端写入注册表失败。
- **新注册的服务显示红点**：后端为新记录写入的状态值不属于页面判定为「在线」的取值集合，因此在状态圆点上呈红色。请以圆点旁的原始状态文本为准，健康探测结论需由后端更新该字段后才会转绿。
- **重启后列表变化**：弹窗提示按「运行期注册表」表述；后端在注册成功后会尝试将注册表落盘持久化，实际重启后是否保留取决于部署时的持久化配置，上线前建议实测一次。
- **页面无编辑与删除入口**：注册信息填错时，当前版本只能通过后端侧清理或重新注册一条正确记录来纠正，页面不提供改删操作。
- **限流与熔断**：副标题所述「统一限流与熔断管理」属于枢纽的定位能力，本页面不提供阈值配置控件，相关参数需在后端配置侧管理。
- **协议选择与实际服务不匹配**：协议字段只作为登记信息与列表图标依据，填错不会被页面拦截，但会影响调用侧的接入判断，注册前请与外部服务提供方确认。

:::tip
为「新能源车维修智能体」接入外部工单、配件库或车辆档案类数据源时，建议在「服务描述」中固定写清「暴露的工具/数据范围」与「归属系统」，因为列表页没有二次编辑入口，描述是后续巡检时唯一的语义线索。
:::
