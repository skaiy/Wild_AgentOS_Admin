# Prompt 版本管理

管理控制台入口：左侧「业务 Agent 开发」分组 →「Prompt版本管理」，hash 路由 `#prompts`。

## 功能定位

页面标题为「Prompt / 模型灰度版本管理」，负责把「提示词模板 + 绑定模型」作为一个可版本化对象来治理，覆盖五类动作：新建版本、激活为生产版本、配置灰度比例、删除版本、以及查看当前版本清单。

核心语义有两条：

- **生产激活**：同一时刻只有一个版本处于激活态（`is_active`），激活新版本即接替旧版本，作为未命中灰度时的兜底版本。
- **灰度分流**：任意版本可单独设置 `canary_percent`。后端按调用方 `user_id` 的稳定哈希分桶（`hash(user_id) % 100`），桶号小于灰度比例即命中该灰度版本；未命中则回落到激活版本；若既无灰度命中又无激活版本，分流接口返回 404。

灰度还支持按租户与角色收窄命中范围（`canary_tenant_ids`、`canary_roles`，空列表表示不限制），这两项由接口承载，当前页面的灰度面板只提交比例。

## 页面结构（区块 / 卡片）

1. **页头**：分支图标 + 标题「Prompt / 模型灰度版本管理」+ 实时状态徽标，右侧「新建版本」按钮。
2. **全局提示条**：操作成功或失败后在页头下方出现一条提示，约 3 秒后自动消失；成功为灰底，失败为红底并展示后端错误文案。
3. **创建面板**（点击「新建版本」后展开）：标题「新建 Prompt 版本」，依次为 `name`、`version`、`model`、`description` 四个单行输入，然后是「模板内容（Jinja2，支持 `{{tenant_id}}` 占位符）」多行文本域，底部为「创建」「取消」。
4. **版本列表**：每个版本为一张卡片。
   - 首行左侧：版本名称、`v` + 版本号（等宽字体）、「生产激活」黑色徽标（仅激活版本）、「灰度 N%」徽标（仅 `canary_percent > 0`）。
   - 首行右侧三个图标按钮：对勾「激活为生产版本」（激活态置灰禁用）、信号图标「配置灰度」、垃圾桶「删除」。
   - 卡片正文：描述、`模型：xxx`、`创建：本地化时间`。
   - 卡片底部：模板内容预览，仅显示前 120 个字符，超出以省略号收尾。
   - 激活版本卡片使用深色描边，其余为浅灰描边。
5. **灰度滑条行**（点击信号图标后在该卡片内展开）：标签「灰度比例」+ 0–100 滑动条 + 实时百分比数值 + 确认按钮（右箭头）+「取消」。
6. **空态与异常态**：无版本时显示「暂无版本，请点击「新建版本」创建第一个 Prompt。」；首次加载显示「加载中…」；后端不可用时显示「后端离线：错误信息（列表为空）」。

## 关键操作

1. **新建版本**：点击「新建版本」→ 填写 `name`、`version`、`model`、`description` → 在模板内容区写入 Jinja2 模板 → 点击「创建」。名称、模板、模型、版本号四项均为必填，任一缺失会提示「名称、模板、模型、版本号均为必填」且不发起请求。创建成功后面板自动收起、表单清空、列表刷新并提示「版本已创建」。
2. **激活为生产版本**：在目标版本卡片点击对勾按钮 → 成功后列表刷新，该卡片出现「生产激活」徽标并提示「已激活」。已处于激活态的版本按钮不可点击。
3. **配置灰度比例**：点击信号图标 → 卡片内展开滑条（初值为该版本当前灰度比例，若为 0 则默认 10）→ 拖动到目标百分比 → 点击右箭头确认 → 提示「灰度 N% 已设置」，滑条自动收起。
4. **关闭灰度**：将滑条拖到 0 并确认，该版本 `canary_percent` 归零，「灰度 N%」徽标随之消失，流量全部回落激活版本。
5. **删除版本**：点击垃圾桶 → 浏览器确认框「确认删除此版本？」→ 确认后删除并刷新列表，提示「已删除」。
6. **验证分流结果**：分流决策由 `GET /api/v1/prompts/resolve` 提供，传入 `tenant_id`、`user_id`、`role` 可查询某个具体调用方实际命中的版本（返回 `version_id`、`name`、`template`、`model`、`is_canary`）。该接口用于运行期与联调核对，页面不直接调用。

:::warning
新建版本默认不是激活态且灰度为 0，即创建后不承接任何流量。上线一个新模板必须显式执行「激活」或「配置灰度」，否则它只是登记在册。
:::

## 字段与参数说明

| 字段 | 含义 | 约束或默认值 |
| --- | --- | --- |
| `id` | 版本唯一标识 | 由后端生成，用于激活、灰度、删除的路径参数 |
| `name` | 版本名称 | 必填 |
| `version` | 版本号 | 必填；列表展示为 `v` + 该值 |
| `model` | 该版本绑定的模型标识 | 必填；卡片以等宽字体展示 |
| `description` | 版本用途说明 | 创建面板中作为普通输入项，未做必填校验 |
| `template` | 提示词模板正文 | 必填；Jinja2 语法，支持 `{{tenant_id}}` 之类占位符；列表仅预览前 120 字符 |
| `is_active` | 是否为当前生产激活版本 | 默认 `false`；全局同时最多一个为 `true`；未命中灰度时的兜底 |
| `canary_percent` | 灰度流量百分比 | 默认 `0`（关闭）；有效范围 0–100，后端按 `min(100)` 收敛；`0` 表示不参与分流，`100` 表示全量 |
| `canary_tenant_ids` | 灰度仅对这些租户开放 | 默认空列表 = 不限租户；页面灰度面板不提交该项 |
| `canary_roles` | 灰度仅对这些角色开放 | 默认空列表 = 不限角色；页面灰度面板不提交该项 |
| `created_at` | 创建时间 | 后端写入 RFC3339 字符串，页面按本地时区渲染 |
| `active_id` | 列表响应中的当前激活版本 ID | 无激活版本时为 `null` |
| 分流参数 `tenant_id` | 分流查询的租户 | 缺省按 `default` 处理 |
| 分流参数 `user_id` | 分流查询的用户，决定哈希分桶 | 缺省按 `anonymous` 处理 |
| 分流参数 `role` | 分流查询的角色 | 缺省为空字符串；空角色只能命中未限定角色的灰度版本 |
| `is_canary` | 分流结果是否来自灰度版本 | 只读；`false` 表示命中的是激活版本 |

## 依赖接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/prompts` | 拉取版本列表、总数与当前激活版本 ID（页面每 30 秒轮询） |
| POST | `/api/v1/prompts` | 创建新版本（提交 name / version / model / description / template） |
| POST | `/api/v1/prompts/{id}/activate` | 将指定版本设为生产激活版本 |
| PUT | `/api/v1/prompts/{id}/canary` | 设置灰度比例，可附带租户与角色白名单 |
| DELETE | `/api/v1/prompts/{id}` | 删除指定版本 |
| GET | `/api/v1/prompts/resolve` | 按 `tenant_id`、`user_id`、`role` 查询实际命中的版本（灰度分流决策） |

创建、激活、灰度、删除四个写操作均由控制台附带管理身份头，以 DA 角色通过后端角色校验。

## 排查与注意事项

- **提示「名称、模板、模型、版本号均为必填」**：前端拦截，四项补齐后再提交。
- **列表显示「后端离线：…（列表为空）」**：接口调用失败，页面不再展示任何版本，请先恢复后端连通性，页面每 30 秒会自动重试。
- **分流接口返回 404「无可用 Prompt 版本」**：既没有命中灰度，也不存在激活版本。先激活一个稳定版本作为兜底。
- **灰度比例已设置但流量看不到变化**：分桶依据 `user_id` 的稳定哈希，同一 `user_id` 的命中结果是确定的，小比例灰度下少量固定用户才会命中；核对方式是用具体 `user_id` 调用分流接口查看 `is_canary`。
- **多个版本同时设了灰度**：后端按遍历顺序返回第一个命中的灰度版本，命中优先级不保证稳定。建议同一时间只保留一个灰度版本。
- **灰度限定了角色却一直不命中**：分流查询若未传 `role`，角色按空字符串处理，无法匹配任何非空 `canary_roles` 白名单，需在调用侧携带真实角色。
- **删除了激活版本**：删除后将没有兜底版本，未命中灰度的请求会拿不到 Prompt。删除前请先激活另一个版本。
- **模板占位符渲染异常**：模板为 Jinja2 语法，`{{ }}` 内的变量名需与运行期实际注入的上下文键一致，例如 `{{tenant_id}}`。

:::tip
为「新能源车维修智能体」调优提示词时的推荐节奏：新建版本 → 用具体 `user_id` 调用分流接口确认命中 → 先设 5%~10% 灰度观察 → 指标稳定后再执行「激活」全量切换 → 保留上一个版本一段时间作为回退位，确认无回退需求后再删除。
:::
