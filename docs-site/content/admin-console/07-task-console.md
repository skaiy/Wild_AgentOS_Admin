# 任务控制台

管理控制台入口：左侧「调试监控与运维」分组 →「任务控制台」，hash 路由 `#console`。

## 功能定位

任务控制台是平台的端到端联调面板：输入一段自然语言任务，由平台自动规划并执行，同时以 SSE 流式回放执行全过程。它同时承担三种视角：

- **发起端**：创建任务并携带用户标识与会话标识，用于会话隔离；
- **观测端**：实时展示模型逐字输出、推理过程、思考链、工具调用与结果、阶段切换、原始事件日志；
- **复盘端**：轮询任务状态与执行明细，汇总总轮次、工具调用次数与 Token 用量。

页面状态（输入内容、任务标识、状态、明细、日志、思考链、工具调用、模型输出、当前阶段）会写入浏览器会话级存储，键名 `wild-agent-os.task-console`，其中日志仅保留最近 500 条。切换页面再回来可继续查看上一次执行结果；关闭浏览器标签页即失效。

## 页面结构（区块 / 卡片）

1. **页头**：终端图标 + 标题「任务控制台」，右侧实时状态徽标（绑定后端健康检查）。
2. **任务输入卡**：
   - 上排两列：「用户标识 (user_id)」「会话标识 (session_id)」；
   - 下方「任务描述」多行文本域，占位提示为输入自然语言任务后由平台自动规划并执行；
   - 操作行：「执行任务」按钮；运行中额外出现「停止」；有日志且未运行时出现「清空」；后端不可达时出现琥珀色提示「后端未连接，请启动后端后再执行」。
   - 运行期间三个输入控件均被禁用。
3. **状态卡（3 张，存在任务标识或状态时显示）**：任务 IRI（等宽字体，可换行）、当前阶段（优先取流式 `phase_change` 推送的阶段，其次取状态接口的 `current_phase`）、进度（运行中显示旋转时钟图标，完成后显示绿色对勾，数值取状态接口进度百分比）。
4. **实时执行区（两列栅格，运行中或已有输出时显示）**：
   - **模型输出（逐字）**：上方紫色区块为「推理过程」（仅在收到推理增量时出现），下方为正文增量拼接结果，运行中带闪烁光标，无内容时显示「等待模型输出…」；
   - **工具调用**：标题右侧为调用条数，每条展示工具名、状态图标（未返回为旋转时钟、成功为绿勾、失败为红色警告）、入参 JSON，返回后追加结果文本（截断展示前 800 字符），无数据显示「暂无工具调用」；
   - **思考链**（有数据时跨两列）：每条展示智能体标识、可选的动作标签与思考正文。
5. **执行日志（深色终端区）**：卡头左侧「执行日志」，运行中右侧显示绿色脉冲点与「实时流式接收」。每行为 `时间 [事件名] 数据`，事件名按类别着色：含 `error`/`fail` 为红、含 `completed` 为绿、含 `phase` 为蓝、含 `thought` 为紫、其余为灰。新日志自动滚动到底部；无日志时显示「等待任务执行…」。
6. **执行统计卡（拿到执行明细后显示）**：总轮次、工具调用、Token 用量（千分位格式化）。

## 关键操作

1. **执行一次任务**：在「任务描述」中输入任务内容 → 按需填写用户标识与会话标识 → 点击「执行任务」。点击后页面先清空上一次的日志、状态、明细、思考链、工具调用与模型输出，再创建任务、记录一条 `task_created` 日志，随后建立 SSE 连接开始接收事件。
2. **指定会话**：会话标识留空时自动生成 `sess_` + 当前时间戳并回填到输入框；填写固定值可让多次执行落在同一会话内。用户标识留空即按匿名处理。
3. **停止接收**：运行中点击「停止」会中断 SSE 连接、结束运行态并记录一条 `user_stopped` 日志。该操作停止的是前端流式接收，不代表后端任务已终止。
4. **清空面板**：非运行态且已有日志时点击「清空」，一次性重置日志、任务标识、状态、明细、思考链、工具调用、模型输出与当前阶段。
5. **跟踪阶段推进**：观察「当前阶段」卡与日志中的 `phase_change` 事件，阶段取值依次为 `plan`、`do`、`check`、`act`、`completed`，事件数据中还包含来源阶段与承担角色（`PA` / `DA` / `CA` / `AA`）。
6. **核对工具调用**：在「工具调用」区按 `call_id` 关联入参与结果，状态图标即为该次调用的成败结论；需要完整原文时到「执行日志」中查看对应 `tool_call` 与 `tool_result` 事件的原始数据。
7. **查看执行统计**：任务结束后「执行统计」显示总轮次、工具调用次数与 Token 用量；状态与明细在有任务标识时会先拉取一次，运行期间每 2 秒刷新一次。

:::warning
「执行任务」在后端健康检查不通过、任务描述为空或任务正在运行时保持禁用。若徽标显示离线，请先恢复后端连通性再执行。
:::

## 字段与参数说明

| 字段 | 含义 | 约束或默认值 |
| --- | --- | --- |
| `user_input` | 任务描述，创建任务时提交的自然语言指令 | 必填（去空格后非空才可提交）；与流式接口的 `prompt` 同源 |
| `user_id` | 用户标识，用于会话隔离 | 可留空，留空按匿名处理（不提交该字段） |
| `session_id` | 会话标识 | 可留空，留空自动生成 `sess_` + 时间戳并回填输入框 |
| `task_iri` | 任务唯一标识 | 由创建接口返回；流式接口未携带时后端自行生成 `iri://stream/` 前缀标识 |
| `include_thought` | 是否推送思考链事件 | 页面固定提交 `true`；后端缺省亦为 `true` |
| `include_tool_calls` | 是否推送工具调用事件 | 页面固定提交 `true`；后端缺省亦为 `true` |
| `current_phase` | 任务当前阶段 | 只读；状态接口在无法解析时回落为 `unknown` |
| `status` | 任务状态 | 只读；状态接口在无法解析时回落为 `queued` |
| `progress.percentage` | 进度百分比 | 只读；缺省按已完成步数与总步数推算，页面无数据时显示 0% |
| `stats.total_turns` | 总轮次 | 只读，来自执行明细接口 |
| `stats.total_tool_calls` | 工具调用总次数 | 只读，来自执行明细接口 |
| `stats.total_tokens` | Token 用量 | 只读，来自执行明细接口，页面按千分位展示 |
| SSE `task_started` | 流建立后的首个事件 | 数据含 `task_iri` 与 `status: started` |
| SSE `llm_content` | 模型输出增量 | 含 `delta`、`is_reasoning`；`is_reasoning` 为真时拼入「推理过程」，否则拼入正文 |
| SSE `thought` | 思考链条目 | 含 `agent_id`、`thought`、`action` |
| SSE `tool_call` | 工具调用发起 | 含 `call_id`、`tool_name`、`arguments`、`agent_id`、`sequence` |
| SSE `tool_result` | 工具调用结果 | 含 `call_id`、`tool_name`、`result`、`success`，按 `call_id` 回填到对应调用 |
| SSE `phase_change` | 阶段切换 | 含 `from_phase`、`to_phase`、`agent_role`、`reason` |
| SSE `agent_status` | 智能体状态变化 | 含 `agent_id`、`role`、`status`、`turn`、`iteration` |
| SSE `error` | 执行错误 | 含 `error_type`、`message`、`agent_id` |
| SSE `completion` | 任务终态 | 含 `status`（`success` 或 `failed`）与 `summary`；收到即结束运行态并关闭流 |

## 依赖接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/v1/tasks` | 创建任务，提交 `user_input` / `user_id` / `session_id`，返回 `task_iri` |
| POST | `/api/v1/tasks/stream` | 建立 SSE 流式执行连接，提交 `prompt` / `task_iri` / `include_thought` / `include_tool_calls` |
| GET | `/api/v1/tasks/{task_iri}/status` | 轮询任务实时状态、当前阶段与进度 |
| GET | `/api/v1/tasks/{task_iri}/details` | 轮询执行明细与统计（总轮次、工具调用、Token 用量） |
| GET | `/health` | 页头实时状态徽标与「执行任务」可用性判断（每 10 秒轮询） |

## 排查与注意事项

- **「执行任务」按钮始终禁用**：三种可能——任务描述为空、上一次任务仍在运行、后端健康检查未通过（此时操作行会出现「后端未连接」提示）。
- **日志出现 `create_error`**：创建任务接口失败，运行态立即结束。日志中携带后端返回的错误信息，据此排查请求体与后端状态。
- **日志出现 `stream_closed` 但没有 `completion`**：流被提前关闭（网络中断、代理超时或后端连接断开）。此时前端已结束运行态，任务在后端可能仍在推进，可依据任务 IRI 通过状态与明细接口继续核对。
- **卡在「启动中…」不动**：进度卡在尚未拿到状态时显示「启动中…」。若长时间无任何事件，请检查后端是否已配置任务执行器；未配置时后端会立即推送失败事件，日志中会出现终态事件与说明。
- **「模型输出」长时间显示「等待模型输出…」**：说明尚未收到 `llm_content` 增量，通常任务仍处于规划阶段，可先看日志中的 `phase_change` 判断进展。
- **工具调用一直是旋转时钟**：对应 `call_id` 的 `tool_result` 尚未到达；若任务已结束仍为该状态，说明该次调用未返回结果，需在日志中查找 `error` 事件。
- **工具结果被截断**：结果卡片仅展示前 800 字符，完整内容请在「执行日志」的 `tool_result` 事件数据中查看。
- **日志条数与刷新后不一致**：会话级存储只保留最近 500 条日志，超出部分不会被恢复。
- **点击「停止」后任务仍在后端执行**：停止仅中断前端 SSE 接收，不会向后端发送取消指令。
- **切页返回后进度未更新**：状态与明细的 2 秒轮询只在运行态下持续；非运行态仅在存在任务标识时拉取一次。需要最新数据时重新执行任务或直接调用状态接口。

:::tip
联调「新能源车维修智能体」时，建议固定一个会话标识多次执行同一类任务，便于在记忆与会话维度对比多轮结果；同时保留任务 IRI，后续可在其他运维页面按该标识回溯执行痕迹。
:::
