# 记忆中心

页面入口：左侧导航「调试监控与运维 → 记忆中心」，深链 hash 为 `#memory`；直达黑板 Tab 的深链为 `#blackboard`。

## 功能定位

「记忆中心 (Memory Center)」统一承载 **Agent 运行时自产的 L0–L3 四层记忆** 的运维视图。它与「知识中心」的分工是：

- **记忆中心**：系统自己写出来的东西——会话上下文、共享黑板节点、检查点、派生投影；
- **知识中心**：人为导入治理的东西——知识库、知识包、本体。

记忆中心由两个 Tab 组成：「系统记忆」看**规模与健康信号**，「L2 黑板」按任务下钻看**节点原文**。前者是聚合统计，后者是逐条明细，排障时通常先看前者定位层级、再用后者定位具体任务。

## 页面结构（区块/Tab/卡片，与代码一致）

页面顶部为标题「记忆中心 (Memory Center)」与副标题，下方为 Tab 栏，含两个 Tab：

| Tab | 标签 | 内容 |
| :-- | :-- | :-- |
| `system` | 系统记忆 | L0–L3 四层实时规模指标（默认打开） |
| `blackboard` | L2 黑板 | 黑板任务列表 + 任务节点抽屉 |

### Tab 一：系统记忆

标题「系统记忆 (System Memory)」+ 实时徽标，下方为 2×2 四张层级卡片：

**L0 长期记忆 (Permanent)** — 副标题「永久沉淀存储 · redb」

- 条目总数
- 检查点 (Checkpoints)
- 已注册技能

**L1 会话记忆 (Session)** — 副标题「会话上下文 · 纯内存」

- 活跃会话数
- 事件总线消息数
- 活跃订阅者
- 在线时附提示：「L1 为进程内会话存储，暂不支持枚举（N/A）」

**L2 黑板 (Blackboard)** — 副标题「跨 Agent 共享黑板 · Oxigraph」

- 知识节点数
- 存储量（自动换算 B/KB/MB/GB/TB）
- 任务数 (Tasks)

**L3 派生投影 (Projection)** — 副标题「按需投影视图 · SPARQL 物化缓存」

- 投影缓存数
- 在线时附提示：「L3 投影为派生缓存，暂未暴露统计接口（N/A）」

数值有三种形态：后端离线显示 `—`；后端在线但该项无枚举接口显示 `N/A`；正常时显示千分位数字。

### Tab 二：L2 黑板

标题「L2 黑板浏览器 (Blackboard)」，副标题「平台运维态 · 跨租户共享记忆，按任务 (task_iri) 定位」，右上角为「刷新」按钮。

**任务列表**（表格，表头显示「共 N 个任务」）

| 列 | 说明 |
| :-- | :-- |
| Task IRI | 任务标识，等宽字体展示 |
| 状态 | `running` 蓝／`completed` 绿／`failed` 红／其他灰 |
| 节点数 | 该任务下的黑板节点数量 |
| 子任务 | 子任务数量 |
| 操作 | 「查看节点」按钮，打开右侧抽屉 |

**任务节点抽屉**（点击「查看节点」从右侧滑出）

- 抽屉头部：标题「任务节点」+ 当前 Task IRI；右上角关闭按钮，点击遮罩亦可关闭。
- 过滤条：角色下拉（全部角色 / `PA (Plan)` / `DA (Do)` / `CA (Check)` / `AA (Act)`）、节点类型输入框（可选，自由文本）、「应用过滤」按钮。
- 节点卡片列表：每张卡片显示节点 IRI、节点类型标签、创建者（`by ...`），下方为格式化后的 JSON-LD 原文代码块（可滚动）。
- 空态：「该任务下无匹配节点」。

## 关键操作（编号步骤）

1. 进入「记忆中心」，默认停留在「系统记忆」Tab，先看四张卡片确认哪一层规模异常。
2. 若判断问题在共享黑板，切到「L2 黑板」Tab（或直接用 hash `#blackboard` 进入）。
3. 在任务列表中按状态定位目标任务：`failed` 优先，其次是长期停留在 `running` 的任务。
4. 点击目标行的「查看节点」，右侧抽屉打开并自动加载该任务的全部节点。
5. 在抽屉过滤条中选择角色（如 `CA (Check)`）以只看检查环节产出的节点，点击「应用过滤」生效。
6. 需要按节点类型收敛时，在「节点类型」输入框填入类型名后再点「应用过滤」；留空表示不限类型。
7. 展开节点卡片中的 JSON-LD 原文核对字段内容，判断是数据缺失还是模型产出格式问题。
8. 关闭抽屉，点击右上角「刷新」重新拉取任务列表以确认状态是否推进。

:::tip
黑板浏览器为**跨租户只读视图**，用于平台侧排障。它不提供节点编辑与删除入口，任何修正都应通过重跑任务或修正上游数据完成。
:::

## 指标与字段说明

| 指标或字段 | 含义 | 判读建议 |
| :-- | :-- | :-- |
| L0 条目总数 `l0_longterm.entries` | 长期存储中的条目数 | 单调增长为正常。若为 `N/A`，说明后端统计失败，需查后端日志 |
| 检查点 `runtime.checkpoints` | 已落盘检查点数 | 与任务量应成正比；任务在跑但检查点不增，说明检查点写入受阻 |
| 已注册技能 `runtime.skills_registered` | 技能注册表条数 | 应与「技能中心」一致 |
| 活跃会话数 `l1_session.sessions` | 会话层活跃会话数 | 当前恒为 `N/A`：L1 为进程内存储，未提供枚举接口，属预期行为 |
| 事件总线消息数 `runtime.events.total_emitted` | 事件总线累计发出条数 | 与「运行时内核」的「事件总线事件数」同源 |
| 活跃订阅者 `runtime.events.active_subscribers` | 当前订阅者数 | 0 表示空载；只增不减需怀疑订阅泄漏 |
| L2 知识节点数 `l2_blackboard.nodes` | 共享黑板节点总数 | 与「任务数」比值即平均每任务节点数，异常偏高说明单任务写入过多 |
| L2 存储量 `l2_blackboard.bytes` | 黑板占用字节 | 页面已换算为可读单位；接近容量规划上限时安排归档 |
| L2 任务数 `l2_blackboard.tasks` | 黑板上的任务数 | 应与「L2 黑板」Tab 任务列表条数一致 |
| L3 投影缓存数 `l3_projection.projections` | 派生投影缓存条数 | 当前恒为 `N/A`：派生缓存未暴露统计接口，属预期行为 |
| Task IRI `task_iri` | 任务唯一标识 | 下钻节点的唯一入口参数，含斜杠，故以查询参数传递 |
| 任务状态 `status` | `running`/`completed`/`failed`/未知 | 长期 `running` 需结合「任务控制台」确认是否卡在某一阶段 |
| 节点数 `node_count` | 任务下节点数 | 为 0 表示任务尚未产出任何黑板节点 |
| 子任务 `children` | 子任务数量 | 大于 0 说明任务被分解，需逐个子任务排查 |
| 节点类型 `node_type` | 节点语义类型标签 | 用于在抽屉中收敛同类节点 |
| 创建者 `created_by` | 写入该节点的 Agent 标识 | 定位是哪个角色写坏了数据 |
| JSON-LD 原文 `json_ld` | 节点内容本体 | 页面会尝试格式化；无法解析时按原文展示，此时应怀疑写入端序列化异常 |

## 依赖接口

| 方法 | 路径 | 用途 |
| :-- | :-- | :-- |
| GET | `/api/v1/memory/unified-stats` | 「系统记忆」Tab 的 L0–L3 与运行时聚合统计，页面每 10 秒轮询 |
| GET | `/api/v1/blackboard/tasks` | 「L2 黑板」Tab 的任务列表，进入 Tab 时加载，点「刷新」手动重载 |
| GET | `/api/v1/blackboard/nodes` | 指定任务的节点明细，支持 `task_iri`、`role`、`node_type`、`cycle_id` 查询参数 |

## 排查与注意事项

- **`N/A` 不是故障**：L1「活跃会话数」与 L3「投影缓存数」当前设计上不提供枚举接口，页面固定显示 `N/A` 并附有文字说明。请勿据此判定后端异常。
- **`—` 才是离线信号**：所有数值统一显示 `—` 时，说明聚合统计接口请求失败，此时应先确认后端连通性。
- **任务列表为空但 L2 节点数不为 0**：说明黑板中存在节点却无可识别的任务摘要，通常是节点未正确挂载 `parent_task`，需检查写入端。
- **抽屉提示「该任务下无匹配节点」**：优先把角色下拉切回「全部角色」并清空「节点类型」再查一次——多数情况是过滤条件过严，而非数据缺失。
- **节点类型输入区分大小写**：该字段以原样字符串传给后端做精确匹配，拼写不一致会直接查不到结果；建议先不带类型查询，再从卡片上的类型标签复制准确值。
- **Task IRI 含斜杠**：接口以查询参数而非路径参数传递 `task_iri`，若自行拼接请求需完成 URL 编码。
- **L2 存储只增不减**：共享黑板不做自动过期清理，历史任务节点会长期驻留。容量治理需在运维侧规划归档策略，页面不提供清理能力。
- **两个 Tab 数据源不同**：「系统记忆」的 L2 数字来自聚合统计接口，「L2 黑板」的任务列表来自黑板任务接口，两者刷新节奏不同（10 秒轮询 vs 手动刷新），短时间内的数字差异属正常。
