# 安全与合规

页面入口：左侧导航「调试监控与运维 → 安全与合规」，深链 hash 为 `#security`。

## 功能定位

「安全与合规 (AI Security)」页面围绕 **OWASP LLM Top 10** 的防护视角，把工具调用侧的 Guard 审计结果集中呈现。当前页面的数据主体是 **ToolGuard**：智能体每次调用工具时，Guard 会在调用前注入约束、在调用后按 Schema 校验输出，并把每次校验写入审计日志。

本页回答的问题是：

1. 平台一共做了多少次工具调用校验，通过率如何；
2. 哪些校验失败了、失败在哪个智能体的哪个工具上、是否发生了重试；
3. 是否存在被拦截的越权/过度代理行为（对应 LLM08 过度代理防护）。

页面为**只读审计视图**，不提供策略开关。防护策略（提示注入防护、幻觉阈值、最大工具调用次数、PII 脱敏、令牌有效期、留存天数等）在「系统设置」的安全与策略区维护。

## 页面结构（区块/Tab/卡片，与代码一致）

**页头**

标题「安全与合规 (AI Security)」+ 副标题「OWASP LLM Top 10 防护、数据脱敏与越权审计」，右侧为实时徽标（绿点「实时」／琥珀点「示例数据」）。

**指标卡区**（四张卡片，一行四列）

| 卡片 | 主数值 | 卡片脚注 |
| :-- | :-- | :-- |
| 工具校验总数（后端离线时标题退化为「提示注入拦截」） | `total_checks` 次 | ToolGuard 实时审计 |
| 校验通过率 | `pass_rate` 百分比（一位小数），后附「N 通过」 | 工具输出 Schema 校验 |
| 敏感信息脱敏 | 固定显示 `—`「暂无数据」 | 姓名/手机号/VIN 脱敏（指标待接入） |
| 失败校验拦截 | `failed_checks` 次 | 过度代理防护 (LLM08) |

:::note
「敏感信息脱敏」卡片当前为占位卡：后端尚未暴露脱敏计数指标，页面固定显示「暂无数据」。这是已知的功能缺口，不是数据加载失败。
:::

**近期安全事件审计日志**（表格）

表头五列，取审计日志**最后 50 条并按时间倒序**展示：

| 列 | 取值规则 |
| :-- | :-- |
| 时间 | `timestamp` 转本地时间字符串 |
| 事件类型 | 固定「工具调用校验」，`pre_injected` 为 true 时追加「· 预注入」 |
| 关联智能体/用户 | `agent_id`（空则 `-`）/ `tool_name` |
| 详情描述 | 有 `error` 显示错误原文；否则显示「校验通过」或「校验未通过」；`retry_count` 大于 0 时追加「(重试 N)」 |
| 处理结果 | `validation_passed` 为 true 显示绿色「通过」，否则显示红色「已拦截」 |

空态两种：后端在线无记录显示「暂无安全事件记录」；后端离线显示「后端离线，无法加载审计日志」。

## 关键操作（编号步骤）

1. 进入「安全与合规」，确认页头徽标为绿色「实时」。
2. 先看「校验通过率」卡片建立基线认知：通过率长期接近 100% 属健康；明显下滑说明有工具输出不符合 Schema。
3. 对照「失败校验拦截」卡片的次数，与通过率交叉验证失败规模。
4. 下滚到审计日志表，按「处理结果」列筛出红色「已拦截」记录（页面无筛选控件，需目视扫描）。
5. 对每条拦截记录，读取「关联智能体/用户」列定位是哪个智能体的哪个工具出问题。
6. 读取「详情描述」列的错误原文，判断是参数缺失、类型不符还是返回结构不符合声明的输出 Schema。
7. 若「详情描述」显示「(重试 N)」，说明 Guard 已触发自动重试仍未通过，需回到「技能中心」核对该工具的输出 Schema 声明是否与实际返回一致。
8. 修正技能声明或提示词后，重新执行一次相关任务（可在「任务控制台」发起），返回本页确认新记录为「通过」。
9. 需要调整防护策略（如最大工具调用次数、PII 脱敏开关、审计留存天数）时，切换到「系统设置」修改，本页仅作效果验证。

:::tip
页面每 8 秒自动刷新一次统计与审计日志，排障时无需手动刷新页面即可看到新产生的校验记录。
:::

## 指标与字段说明

| 指标或字段 | 含义 | 判读建议 |
| :-- | :-- | :-- |
| 工具校验总数 `total_checks` | Guard 累计执行的校验次数 | 与平台工具调用量正相关。为 0 说明尚无工具调用发生，或 Guard 未被触达 |
| 通过次数 `passed_checks` | 校验通过次数 | 与总数之差即失败数 |
| 失败次数 `failed_checks` | 校验未通过次数 | 每一次失败都对应一次工具输出被拦截，需逐条排查 |
| 通过率 `pass_rate` | 通过次数／总次数 | 无记录时后端返回 1.0，页面显示 100%，此为空集约定而非真实健康度 |
| 时间 `timestamp` | 校验发生时刻 | 用于与任务执行时间轴对齐 |
| 工具名 `tool_name` | 被校验的工具标识 | 同一工具反复失败即为定位目标 |
| 智能体 `agent_id` | 触发调用的智能体标识 | 为空显示 `-`，通常是系统内部调用 |
| 预注入 `pre_injected` | 调用前是否注入了约束提示 | true 表示 Guard 已做前置干预；前置干预后仍失败，说明模型未遵循约束 |
| 校验结果 `validation_passed` | 输出是否通过 Schema 校验 | false 即「已拦截」，该次工具结果不会被采信 |
| 重试次数 `retry_count` | 该次校验触发的重试次数 | 大于 0 说明发生过自动纠偏；持续大于 0 会显著抬高延迟与 Token 成本 |
| 错误信息 `error` | 校验失败原因原文 | 定位根因的首要依据，通常直接指出缺失字段或类型冲突 |
| 审计总数 `total` | 审计日志中的记录总条数 | 页面只展示最后 50 条；总数远大于 50 时需结合后端日志做全量分析 |
| 敏感信息脱敏 | 姓名/手机号/VIN 等脱敏计数 | 指标待接入，页面固定显示「暂无数据」 |

## 依赖接口

| 方法 | 路径 | 用途 |
| :-- | :-- | :-- |
| GET | `/api/v1/guard/stats` | Guard 统计（总校验数、通过数、失败数、通过率），页面每 8 秒轮询 |
| GET | `/api/v1/guard/audit` | Guard 审计日志（逐条校验记录），页面每 8 秒轮询，前端取最后 50 条倒序展示 |

两个接口同源于内核内存中的 Guard 审计日志，因此统计与明细天然一致。

## 排查与注意事项

- **通过率显示 100% 但总数为 0**：这是空集约定——无任何校验记录时后端返回通过率 1.0。请以「工具校验总数」为准判断是否真的有校验发生。
- **卡片全部显示 `—`**：说明统计接口请求失败（后端离线），此时审计日志区也会提示「后端离线，无法加载审计日志」。先排查后端连通性。
- **「敏感信息脱敏」永远无数据**：为已知的指标缺口，脱敏能力本身由「系统设置」中的 PII 脱敏开关控制，其效果需通过实际输出抽检验证，不能依赖本卡片。
- **审计日志只保留最近记录**：Guard 审计日志存于内核内存，页面进一步只渲染最后 50 条。后端重启会导致统计与明细归零，请勿把本页当作长期合规留档。合规留档需依赖后端日志与留存策略配置。
- **同一工具反复「已拦截」**：优先怀疑技能声明的输出 Schema 与工具实际返回不匹配，而非模型能力问题。到「技能中心」查看该技能的输出 Schema 与准入流水线记录。
- **重试次数持续偏高**：说明模型频繁产出不合规结构，会同时抬高延迟与成本。可考虑收紧提示词、改用更强的推理模型（在「智能体管理」调整能力槽挂载），或放宽过严的 Schema 约束。
- **审计日志中出现「· 预注入」但仍拦截**：Guard 的前置注入已生效而模型未遵循，属于提示遵循度问题，需从提示词与模型选择两侧改进。
- **本页不做策略变更**：所有策略项（提示注入防护、幻觉阈值、最大工具调用次数、PII 脱敏、令牌有效期、任务/会话/审计留存天数）均在「系统设置」维护，本页仅呈现结果，以确保策略变更可追溯。
- **对外调用的审计不在本页**：入站 API 密钥的调用审计属于另一条链路，请到智能体对外发布与 API 密钥治理相关页面查看，勿在本页寻找外部调用记录。
