# Prompt 版本与灰度

## 1. 版本管理模型

Prompt 以「名称 + 版本」管理，同一名称下同时仅有一个激活版本。页面（`#prompts`）支持：

1. 创建版本：名称、版本号、目标模型与系统提示词。
2. 激活版本：`POST /api/v1/prompts/{id}/activate`。
3. 配置灰度：`PUT /api/v1/prompts/{id}/canary`，设置灰度比例，可附加租户与角色范围。
4. 解析校验：`GET /api/v1/prompts/resolve`，传入租户、用户与角色，查看实际命中的版本。
5. 删除版本：`DELETE /api/v1/prompts/{id}`。

## 2. 灰度分流规则

- 按用户标识稳定哈希取模与灰度比例比较，保证同一用户命中结果稳定。
- 租户列表与角色列表为空表示不限制范围。
- 上线前用 resolve 接口至少验证三类用户：命中灰度、未命中灰度、指定角色。

## 3. 提示词编写约定

| 约定 | 说明 |
| :-- | :-- |
| 变量对齐 | 模板变量必须与运行时传入字段一致，缺失变量会导致占位符残留 |
| 结构化输出 | 需要结构化结果时，在提示词中明确字段与格式，并与 Skill 输出 Schema 对齐 |
| 知识使用 | 明确要求引用检索到的知识来源，避免模型在无命中时臆测 |
| 降级说明 | 约定无命中或信息不足时的回答方式，配合响应中的 `grounded` 判读 |
| 长度控制 | 系统提示词避免冗长重复，为知识上下文预留 Token 预算 |

## 4. 发布流程建议

1. 新版本先以低比例灰度，观察任务控制台输出与安全审计。
2. 用固定问题集对比新旧版本的回答质量与格式稳定性。
3. 比例逐步提升至全量后再激活为默认版本。
4. 出现异常时先将灰度比例归零，再回滚激活版本。

## 5. 排查

| 现象 | 检查项 |
| :-- | :-- |
| 修改未生效 | 是否激活了新版本、灰度比例与用户是否匹配 |
| 输出格式不稳定 | 提示词是否明确格式约束、模型是否具备结构化输出能力 |
| 占位符残留 | 模板变量与运行时字段命名是否一致 |
| resolve 与预期不符 | 检查传入的租户、用户、角色参数与灰度范围配置 |
