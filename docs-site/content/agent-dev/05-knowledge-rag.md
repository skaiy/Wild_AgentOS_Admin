# 知识增强（RAG）配置

## 1. 配置顺序

1. 创建知识库分类。
2. 创建向量库或图谱库并关联分类。
3. 导入并验证数据。
4. 创建知识包，加入需要的知识库。
5. 编辑 Agent，挂载知识包（`knowledge_pack_ids`）。
6. 用已收录问题验证知识命中状态、来源与回答。

## 2. 向量库

| 能力 | 说明 |
| :-- | :-- |
| 文档上传 | `POST /api/v1/kb/bases/{id}/upload`，可设置分块大小、分块策略与重要度阈值 |
| 文本摄取 | `POST /api/v1/kb/bases/{id}/ingest`，直接提交文本 |
| 文档台账 | 查看文档状态：已向量化、仅留底、失败 |
| 原文预览 | 回溯切片来源，核对召回内容 |
| 重新索引 | `POST /api/v1/kb/bases/{id}/reindex`，Embedding 变更或分块调整后使用 |

Embedding Provider、型号、维度与启用状态在模型注册中心维护。向量库维度必须与生效的 Embedding 资源维度一致，否则检索无结果。

## 3. 图谱库

- 每个图谱库使用独立 Oxigraph 命名图。
- 支持 CSV、JSONL、N-Triples 等结构化导入，`clear_before` 控制替换或追加。
- 查询接口 `POST /api/v1/kg/query`，请求字段为 `sparql` 与 `named_graph`；**未指定 `named_graph` 时查询的是联合图**，统计口径会与单库不同。
- 大批量导入应拆批控制单次请求体积，导入后校验实体数、来源数与必要字段。

## 4. 知识包与运行时展开

知识包组合分类、图谱库与向量库。Agent 挂载知识包后，运行时将其展开为命名图集合与向量命名空间，检索结果进入模型上下文，并在响应中返回命中状态与来源。

一个 Agent 可挂载多个知识包；范围越大召回噪声越高，建议按业务场景拆分知识包而非合并成单一大包。

## 5. 验证方法

1. 先用 SPARQL 或向量查询验证数据层可检索（脱离模型）。
2. 再用 Agent 测试提问，检查 `grounded`、`retrieved`、`vector_retrieved`、`sources`。
3. 对照知识原文核对回答中的关键结论与来源页面。

## 6. 排查

| 现象 | 检查项 |
| :-- | :-- |
| 向量查询无结果 | Embedding 是否激活、维度是否一致、文档是否完成索引 |
| SPARQL 查询为空 | 命名图是否正确、IRI 与属性路径是否匹配、导入批次是否成功 |
| Agent 无知识命中 | 知识包 ID、图谱库 ID、命名图数据、问题中的关键实体是否在库 |
| 召回噪声大 | 缩小知识包范围、调整分块大小、提高重要度阈值 |
| 导入报请求体过大 | 拆分批次导入，必要时降低单批记录数 |
