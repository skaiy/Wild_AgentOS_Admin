# Wild AgentOS（如野智能体操作系统）项目说明

> 当前版本：**v0.2.0-alpha**（Alpha 阶段，功能与接口仍在迭代，暂不适用于生产环境）
> 更新日期：2026-07-26

Wild AgentOS 是一套工业级多智能体协同与控制操作系统，目标是提供可驾驭集体智能、可自适应任务复杂度的智能体基础设施。后端完全基于 **Rust** 编写，保证高并发与内存安全；管理控制台基于 **React 19 + TypeScript + Vite 6 + Tailwind CSS 4** 构建，用于智能体配置、知识治理、模型路由、任务调试与安全审计。

平台由两个工程组成：

| 组成 | 职责 |
| :-- | :-- |
| 后端内核 `Wild_AgentOS` | 智能体生命周期编排、五层记忆管理、嵌入式 Hyperspace 向量数据库、知识图谱与感知服务 |
| 管理控制台 `Wild_AgentOS_Admin` | Web 控制面：智能体、知识、技能、Prompt、模型注册、任务监控、安全治理与平台文档 |

## 1. 总体架构

![Wild AgentOS 系统架构](/manual-assets/system-architecture.svg)

平台自上而下由用户接入渠道、React 管理控制面、Rust 服务接入层、Agent 运行时、知识与数据资源、模型路由与运维能力组成。管理端负责配置 Agent、Skill、Prompt、知识资源与模型资源；运行时负责解析挂载关系、构建 RAG 上下文、调用模型并记录任务状态与审计信息。

### 1.1 分层职责

| 层级 | 当前职责 |
| :-- | :-- |
| 用户与接入渠道 | 管理人员与 Agent 开发者通过浏览器使用控制台；外部系统可使用 REST、gRPC、OpenAI 兼容接口调用 |
| React 管理控制面 | Agent、Skill、Prompt、知识中心、模型注册中心、安全配置、任务与运行监控 |
| Rust 服务接入层 | Axum REST/SSE、OpenAI 兼容接口、Tonic gRPC、身份解析、RBAC 与调用配额 |
| Agent 运行时 | Agent 配置解析、技能与知识包挂载、模型能力槽解析、任务编排、RAG 上下文构建、工具调用与审计 |
| 知识与数据资源 | 知识分类、向量库、图谱库、知识包、Oxigraph 命名图、Hyperspace 向量索引与 L0-L3 记忆数据 |
| 模型路由 | Provider 与型号注册、远端型号发现、连通性测试、chat/vision 能力槽挂载与 OpenAI 兼容路由 |

### 1.2 内核关键能力

1. **通用化 PDCA 编排引擎（PA/DA/CA）**
   将「规划-执行-检查-改进」循环升级为自适应任务执行模型：依据 **5W2H 本体元数据** 自动判定任务复杂度，划分 **L0 至 L6 共 7 个层级**（从即时问答到递归重构、紧急热修复），动态选择 Supervisor / Doer / Checker 等角色组合。
2. **五层记忆与缓存系统**
   模仿 CPU 缓存层级：`L0` redb 磁盘持久化与 Hyperspace 向量库 → `L1` 会话上下文 → `L2` Oxigraph 内存工作黑板 → `L3` SPARQL 投影视图。多智能体一致性引入 **MESI 协议**，并以扩散激活算法做智能预取，冷加载感知延迟最高降低约 90%。
3. **Hyperspace 嵌入式向量引擎**
   独立 Rust crate（`crates/hyperspace-engine`），无需外部向量数据库依赖；支持 HNSW 近似最近邻检索、预写日志（WAL）与 CRC32 校验，并可运行时切换 Poincaré、Cosine、Euclidean、Lorentz 等度量空间。
4. **技能图谱认知网络（Skill Graph）**
   基于超图结构的动态认知图谱，支持前置依赖、组合、关联、替代、扩展、泛化 6 种语义链接，集成 PageRank、社区发现与因果根因分析，并提供 6 项形式化不变式检查与快照版本回退。
5. **JSON-LD 1.1 数据总线**
   基于 W3C 标准实现鸭子类型与实体自动对齐，规避多工具间字段冲突。

## 2. 接口与通信模式

| 网关 | 说明 |
| :-- | :-- |
| HTTP / SSE（Axum） | 管理面 RESTful 接口（`/api/v1/...`），覆盖智能体、知识、技能、Prompt、模型与运维；任务执行与日志通过 SSE 推送 |
| gRPC（Tonic） | 基于 `proto/pdca_core.proto` 暴露高性能 RPC（`SeKernelServiceServer`），支撑多节点联邦与高性能执行端点 |
| OpenAI 兼容层 | 内置 `/v1/models` 与 `/v1/chat/completions`，第三方 SDK 可将 Agent 直接当作模型调用 |
| MCP | 可登记 Model Context Protocol Server，作为外部工具接入通道 |

## 3. 知识增强与模型路由链路

**知识增强（RAG）**

1. 在知识中心创建分类、向量库或图谱库。
2. 将一个或多个知识库组合为知识包。
3. Agent 通过 `knowledge_pack_ids` 挂载知识包。
4. 对话时运行时将知识包展开为 Oxigraph 命名图与向量命名空间。
5. 图谱查询与向量召回结果进入模型上下文，响应中返回命中状态与来源信息。

**模型路由**

1. 在模型注册中心配置 OpenAI 兼容 Provider。
2. 从 Provider 拉取可用型号，登记为模型资源。
3. 使用连通性测试验证模型端点。
4. Agent 的 `model_mounts.chat` 或 `model_mounts.vision` 指向模型资源。
5. 运行时按请求内容解析能力槽并调用对应 Provider；未命中时回退网关默认模型。

## 4. 业务定位与示例场景

平台面向工业级垂直领域（例如新能源汽车后市场、制造与售后服务等场景）提供高确定性、可自我审计、可控成本、具备文件系统感知能力的智能体运行底座。当前随平台提供的示例业务为「新能源车维修智能体」：

| 项目 | 示例数据 |
| :-- | --: |
| 知识来源页面（dianchema.com） | 2,213 |
| 归并知识记录 | 2,033 |
| RDF 三元组 | 91,494 |
| 维修业务 Skill | 6 |

示例业务链路：

`维修问题 → 新能源车维修智能体 → 故障码/警告灯/安全评估等 Skill → 全量维修知识图谱 → 已注册模型 → 带知识命中状态的回答`

已配置的业务 Skill 包括故障码诊断查询、仪表警告灯分诊、行驶安全评估、维修方案编排、车型适配分析与跨品牌故障对比。

## 5. 能力边界与后续集成方向

当前平台重点为 Agent 配置、知识增强问答、模型路由与运行管理。以下能力需在接入对应业务系统后实现并验证：

- VIN、BOM、配件库存与维修工单系统联动。
- 产线工业相机、IoT 设备与实时告警接入。
- 车机、移动端、客服渠道与保险定价系统集成。
- 基于业务数据的维修成本核算、库存调拨与工单自动派发。

工程化方向：

- 多租户隔离与安全沙箱策略验证（`X-Identity` 全链路审计、跨租户越权阻断）。
- 弱算力私有化部署下的性能调优（L2 内存占用、缓存清理、私有模型冷启动与 L3 预取命中率）。

外部系统接入可通过 MCP、REST/gRPC 接口或专用 Skill 扩展，并按实际数据权限配置身份、角色与审计策略。
